Title: [BUG-002] Inspection with every item N/A is saved as score 100 and risk "low"
Labels: bug, severity: major, priority: high, backend, scoring, needs-owner-decision

## Summary
When every checklist item is answered N/A, nothing was checked. The inspection still gets score 100 and risk "low", and the lab gets `lastScore` 100.

**Requirement basis:** reasonable expectation. README section 1, line 25 gives `score = passed / (passed + failed) x 100`. With only N/A this is 0 / 0, so the README does not define the result.

**Severity:** Major. An unchecked lab looks perfect in a safety system.
**Priority:** High, after the owner confirms the rule

## Environment
Windows 11 (10.0.26200), Node v24.14.0, Express 4.22.3, Mongoose 8.24.5, in-memory MongoDB, Jest 30.5.2 + Supertest 7.3.2

## Steps to reproduce
Data: `backend/seed.js`. Lab CH-05 has one scheduled inspection with 8 items (3 are critical).
1. Log in as the assigned inspector (demo account of README section 3).
2. `GET /api/inspections/<CH-05 inspection id>` and copy the 8 item ids.
3. `PUT /api/inspections/<id>/submit` with every item "na":
   ```json
   {"summary":"QA run","responses":[{"_id":"<item 1 id>","result":"na","remarks":""}, "... the same for items 2 to 8"]}
   ```
4. `GET /api/labs/<CH-05 id>`

## Expected result
Status 400, or status 200 without score 100 and without "low". `lastScore` of the lab is not 100.

## Actual result
```
TC-INS-05.1  Received string: "status 200, score=100, risk=low"
TC-INS-05.2  Expected: not "lastScore=100"   (failed, so the value was lastScore=100)
```

## Evidence
- Failing tests: TC-INS-05.1, TC-INS-05.2 in `qa/06-automation-cicd/known-defects/inspections.test.js`
- `qa/evidence/phase2-known-defects.log` lines 429-454
- `qa/evidence/phase2-rerun-known-defects.log` lines 428-449
- Root cause analysis: `qa/08-defects/rca-5-whys.md`

## Code location
- `backend/models/Inspection.js:33` (`total === 0 ? 100 : ...`) and `:38`
- `backend/controllers/inspectionController.js:78` and `:88`

## Suggested fix
The owner chooses and documents the rule:
- A: answer 400 when every answer is N/A, or
- B: save no score and a level "not assessed", and do not change `lastScore`
