Title: [BUG-003] Inspector can read the inspection of another inspector (GET /api/inspections/:id has no owner check)
Labels: bug, security, severity: moderate, priority: medium, backend, needs-owner-decision

## Summary
`GET /api/inspections/:id` returns the inspection of any inspector to any other inspector.

**Requirement basis:** documented requirement. README section 1, line 37: "View inspections: all / own / completed reports only" (admin / inspector / technician).

**README contradiction, a ruling is needed:** README section 4, line 125 says `GET /api/inspections/:id` is for "any" role. We follow section 1, because the list route shows an inspector only the own inspections, and "any" is not complete (a technician gets 403 for a scheduled inspection). If "any" is right, close this issue as "not a defect" and correct line 37.

**Severity:** Moderate. Read only, only for a logged-in inspector who knows the id.
**Priority:** Medium

## Environment
Windows 11 (10.0.26200), Node v24.14.0, Express 4.22.3, Mongoose 8.24.5, in-memory MongoDB, Jest 30.5.2 + Supertest 7.3.2

## Steps to reproduce
Data: `backend/seed.js`, plus a second inspector (B) with one scheduled inspection.
1. Log in as inspector A.
2. `GET /api/inspections`. The inspection of B is not in the list (correct).
3. `GET /api/inspections/<id of the scheduled inspection of B>`
4. Log in as inspector B.
5. `GET /api/inspections/<id of a scheduled inspection of A>`
6. `GET /api/inspections/<id of a completed inspection of A>`

## Expected result
Step 3: 403 or 404. Steps 5 and 6: 403.

## Actual result
Status 200 with the inspection in all three cases. Example (step 3, shortened, names removed):

```
Expected status: 403 or 404
Actual status:   200
Actual body:     {"_id":"...","lab":{...,"code":"HV-01",...},...,"inspector":{"_id":"...","name":"<inspector B>","email":"<email of B>"},"status":"scheduled","responses":[...
```
